💻 Machete de Git + GitHub

Repaso práctico para proyectos y trabajo en equipo

Este machete está pensado para trabajar con el flujo que utilizan en la facultad:

main → dev → rama de trabajo → dev → main

main = versión final / estable

dev = integración de los cambios

Ramas de trabajo = donde cada integrante desarrolla una funcionalidad.

1. 🚀 Empezar un proyecto desde cero

Primero creamos la carpeta y entramos en ella: 

mkdir MiProyecto
cd MiProyecto

Inicializamos Git: 

git init

Comprobamos el estado: 

git status

Agregamos los archivos al staging: 

git add .

Creamos el primer commit: 

git commit -m "Primer commit"

2. 🌿 Crear la estructura de ramas

El flujo recomendado para la facultad: 

main
 │
 └── dev
      ├── login
      ├── registro
      ├── perfil
      └── otra-funcionalidad

Crear la rama dev

git switch -c dev

Crear una rama de trabajo

git switch dev
git switch -c login

De esta manera la rama login nace a partir del estado actual de dev.

3. 👀 ¿En qué rama estoy?

git branch

La rama actual aparece marcada con *.

También podemos usar: 

git status

Git mostrará algo parecido a: 

On branch dev

4. 🔄 Cambiar de rama

git switch main
git switch dev
git switch login

5. 🌐 Subir el proyecto a GitHub

Primero creamos un repositorio vacío en GitHub.

Luego conectamos nuestro proyecto local: 

git remote add origin URL_DEL_REPOSITORIO

Ejemplo: 

git remote add origin https://github.com/usuario/MiProyecto.git

Comprobamos la conexión: 

git remote -v

Subimos main por primera vez: 

git branch -M main
git push -u origin main

6. ⬆️ Subir cambios a GitHub

git add .
git commit -m "Descripción del cambio"
git push

Si es una rama nueva y es la primera vez que la subimos: 

git push -u origin nombre-rama

Después normalmente alcanza con: 

git push

7. 👥 Trabajar en equipo: CLONE

Si un compañero necesita obtener el proyecto por primera vez: 

git clone URL_DEL_REPOSITORIO

Después entra a la carpeta: 

cd MiProyecto

Y puede comprobar: 

git status
git branch

8. 💻 Trabajar desde otra PC

Si el proyecto ya está en GitHub, en la otra computadora: 

git clone URL_DEL_REPOSITORIO
cd MiProyecto

Antes de empezar a trabajar: 

git pull

Después trabajamos normalmente: 

git add .
git commit -m "Descripción del cambio"
git push
💡 Cuando volvés a la otra PC, hacé git pull antes de continuar.

9. ⭐ Flujo de trabajo de la facultad

Este es el flujo más importante para practicar:

MAIN
↓
DEV
↓
RAMA DE TRABAJO
↓
DEV
↓
MAIN

1️⃣ Partir desde dev

git switch dev
git pull
git switch -c login

2️⃣ Trabajar en nuestra rama

# modificamos archivos...

git status
git add .
git commit -m "Agrego login"
git push -u origin login

3️⃣ Integrar la rama en dev

git switch dev
git pull
git merge login
git push

En un equipo real también puede hacerse mediante un Pull Request en GitHub.

4️⃣ Cuando el proyecto está listo: dev → main

git switch main
git pull
git merge dev
git push

10. 🔎 Ver qué cambió

Ver estado

git status

Ver diferencias

git diff

Ver historial

git log

Historial resumido

git log --oneline

11. ↩️ Deshacer cambios

Si modificamos un archivo pero todavía NO hicimos git add: 

git restore archivo.js

Para descartar todos los cambios no commiteados: 

git restore .
⚠️ Cuidado: estos cambios se descartan.

12. 🧹 Quitar archivos del staging

git restore --staged .

Los archivos NO se borran. Simplemente dejan de estar preparados para el commit.

13. 🔀 Merge

Para incorporar una rama de trabajo a dev: 

git switch dev
git pull
git merge login
git push

De esta manera los cambios de login pasan a dev.

14. ⚠️ Conflictos

Si dos personas modifican la misma parte de un archivo, Git puede generar un conflicto.

Primero: 

git status

Resolvé el conflicto en el archivo y después: 

git add .
git commit -m "Resuelvo conflicto"
git push

15. 🗑️ Eliminar una rama

Eliminar rama local: 

git branch -d login

Eliminar rama del repositorio remoto: 

git push origin --delete login

16. ⭐ SÚPER MACHETE FINAL

# INICIAR PROYECTO
git init

# ESTADO
git status

# RAMAS
git branch
git switch -c nombre-rama
git switch nombre-rama

# GUARDAR CAMBIOS
git add .
git commit -m "mensaje"

# SUBIR
git push

# BAJAR CAMBIOS
git pull

# CLONAR
git clone URL

# HISTORIAL
git log --oneline

# CONECTAR CON GITHUB
git remote add origin URL

# PRIMER PUSH DE MAIN
git branch -M main
git push -u origin main

# PRIMER PUSH DE UNA RAMA
git push -u origin nombre-rama

# MERGE A DEV
git switch dev
git pull
git merge nombre-rama
git push

# MERGE DEV → MAIN
git switch main
git pull
git merge dev
git push

# DESHACER CAMBIOS
git restore archivo.js
git restore .

# SACAR DEL STAGING
git restore --staged .

# BORRAR RAMA LOCAL
git branch -d nombre-rama

# BORRAR RAMA REMOTA
git push origin --delete nombre-rama

🏆 Regla de oro

main ← dev ← rama de trabajo

Trabajás → commit → push
↓
Rama → dev → main

💡 Antes de empezar a trabajar: 

git pull

💡 Antes de subir: 

git status

💡 Usá mensajes de commit que expliquen qué hiciste.
